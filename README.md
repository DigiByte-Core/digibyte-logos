# DigiByte Logos & Brand Assets

![DigiByte horizontal logo](Logos%20Vector/DigiByte%20Logo_Horizontal.svg)

A collection of DigiByte and DigiByte ecosystem logos, symbols, icons, and
supporting artwork in vector and bitmap formats.

## About this repository

This repository provides reusable artwork for DigiByte and related ecosystem
projects, including Digi-ID, DigiAssets, and DigiDollar. It contains scalable
vector masters, bitmap exports, and platform-specific icons for websites,
applications, wallets, exchanges, listings, documentation, and community
media.

Use the supplied vector artwork whenever possible. For fixed-size placements,
select the closest matching PNG or platform icon instead of enlarging a
smaller bitmap.

## Recommended usage

For a clear and consistent presentation:

- Use artwork directly from this repository rather than recreating it.
- Preserve the original proportions, spacing, alignment, and orientation.
- Maintain sufficient clear space around the logo and ensure strong contrast
  with its background.
- Select an existing light, dark, transparent, or solid-background variant
  appropriate for the placement.
- Avoid stretching, skewing, rotating, cropping, recolouring, outlining, or
  rearranging the artwork.
- Avoid adding gradients, shadows, glow effects, textures, or decorations
  unless they are part of a supplied asset.
- Keep symbols and wordmarks in their provided relationship; use a
  symbol-only asset when space is limited.
- Follow additional instructions and attribution included inside a
  collection-specific README.

## Contributing

Contributions that improve the accuracy, usability, accessibility, or
platform coverage of this asset library are welcome.

Before opening a pull request:

1. Place files in the appropriate existing collection and use clear,
   consistent filenames.
2. Include a clean vector master where possible and only the bitmap sizes
   needed for real deployment targets.
3. Confirm that files open and render correctly in commonly used tools and
   browsers.
4. Preserve transparency where expected and document intentionally opaque
   backgrounds.
5. Document colours, dimensions, intended use, source material, attribution,
   and any font or third-party licensing requirements.
6. Keep the pull request focused and explain what was added or changed and
   why.

When updating an established design, avoid silently replacing existing
artwork. Explain the reason for the change and provide side-by-side previews
when visual review would be helpful.
